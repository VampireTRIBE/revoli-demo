# Media Tab UI Labels, Data Sources, and Formulas

## 1. Purpose

This document explains every data label currently visible on the Media tab. It states what the label means, whether its value is taken directly from a workbook or calculated by the server, the workbook sheet used, and the formula used.

This document covers the current `/media` page only. It does not cover API-only funnel or organic modules that are not displayed on this page.

## 2. Source workbooks

| Short name | Workbook | Sheets used for visible Media data |
| --- | --- | --- |
| Site workbook | `Rivoli Shop Segmentation with reconciled campaigns .xlsx` | Monthly sheets such as `Jan 2026` and `Aug 2026`; `Campaign Brand Map`; `Reconciliation` for detection and checks |
| Google workbook | `Rivoli-Google-Brand-Spend-Jan-Sep-2026.xlsx` | `Brand x Month`; `Stage x Month (AED)` for zero-activity and checks |

Detailed monthly sheets own the displayed values. Control sheets can create warnings but do not replace detailed data.

## 4. Year, Month, Segment, and Brand filters

### Year and Month

Reporting periods are detected from monthly sheets in the Site workbook. A sheet name must follow the pattern `Jan 2026`, `Feb 2026`, and so on.

| Visible label | Data source and behavior |
| --- | --- |
| `Year` | Years found in the Site workbook monthly sheets. `All Years` removes the year filter. |
| `Month` | Months inside the selected year. `All Months` aggregates imported months in that year. |
| `(partial)` | Added when the opening rows of a monthly sheet identify a partial period. |

The page initially selects the latest complete month. If no complete month exists, it selects the latest available month.

### Segment and Brand

Labels come from:

- Google `Brand x Month`: `Segment` and `Brand / rollup`;
- Meta `Brand x Month (spend)`: `Segment` and `Brand`;
- Site monthly sheets: `Final segment` and `Final canonical brand`.

| Visible label | Meaning |
| --- | --- |
| `Segment` | Filters every visible calculation by the selected Segment. |
| `All Segments` | Uses all matching Segment rows. |
| `Brand` | Filters every visible calculation by the selected Brand. |
| `All Brands` | Uses all Brands inside the selected period and Segment. |

Each Segment and Brand option displays directional ROAS. A fallback is clearly marked:

```text
Label - 2.30x
Label - 2.30x (Segment basis)
Label - 2.30x (Overall basis)
```

The first usable calculation level is selected:

```text
Brand ROAS = exact Brand site revenue / exact Brand paid spend
fallback = mapped Segment site revenue / mapped Segment paid spend
fallback = overall period site revenue / overall period paid spend
```

```text
Segment ROAS = exact Segment site revenue / exact Segment paid spend
fallback = overall period site revenue / overall period paid spend
```

Changing Segment resets Brand to `All Brands`.

## 5. KPI cards

### Blended ROAS

Visible data includes the `Blended ROAS` ratio, its revenue/spend support line, optional `Segment basis` or `Overall basis`, and a benchmark score bar.

Sources:

- revenue: Site monthly sheet, `Item revenue (AED)`;
- Google spend: Google `Brand x Month[Spend (AED)]`;
- Meta spend: Meta `Brand x Month (spend)[Spend (AED)]`.

```text
Total Paid Spend = Google Spend + Meta Spend
Blended ROAS = Reconciled Site Revenue / Total Paid Spend
```

For a selected Brand or Segment, the fallback order in section 4 is used. The revenue/spend support line shows the actual numerator and denominator used. This is directional, not verified paid-attributed ROAS. Returns can produce negative revenue and negative ROAS; the application keeps that result.

### Blended CAC

Visible data includes `Blended CAC`, AED value, `AOV AED ... to CAC is ...% of AOV`, and a benchmark score bar.

Sources:

- Google `Brand x Month`: `Spend (AED)` and `Conversions`;
- Meta `Brand x Month (spend)`: `Spend (AED)` and `Platform-claimed purchases`;
- Site monthly sheet: `Items purchased` and `Item revenue (AED)`.

```text
Platform Conversions = Google Conversions + Meta Platform-claimed Purchases
Blended CAC = Total Paid Spend / Platform Conversions
Site AOV = Site Revenue / Site Purchases
CAC as % of AOV = Blended CAC / Site AOV
```

This is platform-claimed CAC, not verified new-customer CAC.

### Blended CTR

Visible data includes `Blended CTR`, the percentage, paid impressions, and a benchmark score bar.

Sources:

- Google `Brand x Month`: `Interactions` and `Impressions`;
- Meta `Brand x Month (spend)`: `Link clicks` and `Impressions`.

```text
Paid Traffic Actions = Google Interactions + Meta Link Clicks
Paid Impressions = Google Impressions + Meta Impressions
Blended CTR = Paid Traffic Actions / Paid Impressions
```

This is technically a blended response rate because Google supplies interactions while Meta supplies link clicks.

### Platform conversions

Visible data includes `Platform conversions`, the claim count, and a comparison with site purchases.

```text
Platform Conversions =
  Google Brand x Month[Conversions]
  + Meta Brand x Month (spend)[Platform-claimed purchases]

Site Purchases = Site monthly sheet[Items purchased]
```

Platform conversions are advertising-platform claims. They can exceed site purchases because Google and Meta can claim the same order.

## 6. `By platform` table

The heading displays `By platform — reporting period`. The table contains Meta Ads and Google Ads rows.

| UI column | Meaning | Workbook field or formula |
| --- | --- | --- |
| `Platform` | Advertising platform | Assigned from the Google or Meta source |
| `Spend` | Paid spend in AED | Google `Brand x Month[Spend (AED)]` or Meta `Brand x Month (spend)[Spend (AED)]` |
| `Impr.` | Impressions | Matching platform `Impressions` |
| `CTR` | Google interaction rate or Meta link CTR | Google: `Interactions / Impressions`; Meta: `Link clicks / Impressions` |
| `Conv.` | Platform claims | Google `Conversions` or Meta `Platform-claimed purchases` |
| `CAC` | Platform claimed CAC | `Platform Spend / Platform Claims` |
| `ROAS` | Directional platform ROAS | `Platform Directional Revenue / Platform Spend` |

Platform directional revenue is allocated inside each Segment:

```text
Platform Spend Share in Segment =
  Platform Spend in Segment / Google + Meta Spend in Segment

Platform Directional Revenue =
  sum(Segment Site Revenue x Platform Spend Share in Segment)

Platform ROAS = Platform Directional Revenue / Platform Spend
```

This prevents Segment revenue from being counted twice between Google and Meta. It is not verified platform-attributed revenue.

## 7. `Campaign ROAS (spend > AED 300)` chart

The chart displays up to 12 campaigns with spend above AED 300 and a usable directional ROAS, sorted by highest ROAS first.

- Desktop uses `G:` for Google and `M:` for Meta.
- Mobile shows the full platform name, campaign name, ROAS, bar, and spend.
- Underscores in campaign names are replaced with spaces for display only.
- Green means ROAS is at least `2.50x`.
- Yellow means ROAS is at least `1.50x` and below `2.50x`.
- Red means ROAS is below `1.50x` or unavailable.

Desktop hover shows campaign, platform, `Directional ROAS`, `Spend`, and the mapped basis.

```text
Campaign ROAS = exact mapped Brand directional return
fallback = mapped Segment directional return
fallback = overall period directional return
```

Campaigns in the same mapped group can have the same ROAS. This is directional revenue coverage, not campaign-attributed revenue.

## 8. `Campaign detail` table

The `Meta` and `Google` buttons switch the platform. Rows are sorted from highest to lowest spend.

| UI column | Meaning | Source or formula |
| --- | --- | --- |
| `Campaign` | Cleaned campaign name | Google `Campaign Brand Map[Campaign]` or Meta `Meta Campaign Brand Map[Campaign]` |
| `Spend` | Campaign spend in AED | Google direct `Cost (AED)`; Meta allocated monthly spend |
| `CTR` | Campaign response rate | Google `Interactions / Impressions`; Meta `Link clicks / Impressions` |
| `Conv.` | Platform-claimed campaign conversions | Google direct `Conversions`; Meta allocated claims |
| `ROAS` | Mapped directional return | Exact Brand, then Segment, then overall fallback |

### Google campaign data

Google campaign detail comes from the Site workbook `Campaign Brand Map` sheet:

- `Month`;
- `Campaign`;
- `Canonical brand(s) for tech`;
- `Final segment(s)`;
- `Cost (AED)`;
- `Conversions`;
- `Impressions`;
- `Interactions`.

### Meta monthly campaign data

The Meta workbook supplies monthly Brand totals from `Brand x Month (spend)` and campaign mapping plus nine-month spend from `Meta Campaign Brand Map`.

```text
Campaign Share =
  Campaign Spend 9-mo / Total Spend 9-mo for the Brand's mapped campaigns

Monthly Campaign Spend = Monthly Brand Spend x Campaign Share
Monthly Campaign Claims = Monthly Brand Claims x Campaign Share
Monthly Campaign Impressions = Monthly Brand Impressions x Campaign Share
Monthly Campaign Link Clicks = Monthly Brand Link Clicks x Campaign Share
```

If no Meta map exists for a monthly Brand row, the application keeps an `Unallocated Meta campaign detail` row instead of dropping the total.

## 9. Attribution and source-check labels

### `Attribution caveat`

The note compares platform-reported conversions with actual site purchases:

```text
Platform-reported conversions = Google claims + Meta claims
Actual site purchases = Site monthly sheet[Items purchased]
```

It explains that platform claims can overlap and that platform and campaign ROAS are directional. `iCAC` remains unavailable because it requires a geo-holdout or spend-pause test.

### `Source check`

This line appears when warning-level workbook controls differ from detailed data. Checks use:

- Control workbook `Claims vs Verified (monthly)`;
- Control workbook `Segment Plot (9 mo)`;
- Google `Stage x Month (AED)`;
- Meta `Stage x Month (spend AED)`;
- Site workbook `Reconciliation`.

Warnings do not overwrite displayed values. Detailed monthly rows remain the calculation source.

## 10. `How this score is computed`

The visible table columns are `Metric`, `Value`, `Benchmark (0 to 100)`, `Weight`, and `Score`.

| Metric | Bad anchor | Good anchor | Weight |
| --- | ---: | ---: | ---: |
| `Blended ROAS` | `1.00x` | `4.00x` | 40% |
| `CAC / AOV` | 100% | 30% | 30% |
| `Blended CTR` | 0.50% | 2.00% | 30% |

```text
Metric Score =
  round((Metric Value - Bad Anchor) / (Good Anchor - Bad Anchor) x 100)
```

The server limits an available metric score to a minimum of `2` and a maximum of `100`.

```text
Reference Media Score =
  sum(Available Metric Score x Weight)
  / sum(Weights for Available Metrics)
```

The result appears beside `Media` in the navigation. It reproduces the reference UI method and is not an approved full Media score.

## 11. Display rules

| Display | Rule |
| --- | --- |
| `AED` | Currency values use UAE dirham formatting. |
| `%` | Decimal rates are formatted as percentages. |
| `x` | ROAS uses two decimal places, such as `2.30x`. |
| `N/A` | The denominator is zero or required source data is absent. |
| `...` beside Media | The reference score is loading. |
| Negative ROAS | Kept when reconciled returns make site revenue negative. |

The server sums additive inputs before calculating ratios. It never averages monthly CTR, CAC, AOV, or ROAS.

## 12. Interpretation rules

- Site revenue is reconciled site revenue, not verified paid-attributed revenue.
- Google conversions and Meta purchases are platform claims, not deduplicated orders.
- Blended CAC is not new-customer CAC.
- Google CTR uses interactions; Meta CTR uses link clicks.
- Meta monthly campaign values are allocated estimates.
- Platform and campaign ROAS values are directional.
- The reference Media score is a three-metric UI score, not the approved full business score.
